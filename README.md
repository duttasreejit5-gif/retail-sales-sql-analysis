# Retail Sales Analytics using SQL

## Project Overview

This project focuses on analyzing retail sales data using **MySQL** to understand product performance, customer purchasing behaviour, sales trends, and key business metrics.

The project follows a structured data-analysis workflow:

**Data Cleaning → Exploratory Data Analysis → Business Analysis → Business Insights**

The analysis was performed using three primary datasets:

- `product_inventory`
- `customer_profiles`
- `sales_transaction`

---

## Business Objective

The objective of this project is to transform raw retail transaction data into meaningful business insights using SQL.

The analysis focuses on:

- Cleaning and validating raw datasets
- Identifying missing values and duplicate records
- Cleaning and converting transaction dates
- Understanding overall sales and revenue performance
- Evaluating product and category performance
- Analysing customer purchasing behaviour
- Segmenting customers based on purchase quantity
- Identifying high-value and frequent customers
- Analysing customer loyalty and repeat purchasing behaviour
- Supporting business decisions through data-driven insights

---

## Dataset

The project uses three primary tables.

### 1. `product_inventory`

Contains information about products available in the inventory.

**Key columns:**

- `ProductID`

### 2. `customer_profiles`

Contains customer demographic and profile information.

**Key columns:**

Contains transaction-level sales information.

**Key columns:**

# 01 — Data Cleaning

The data-cleaning stage was performed to prepare the raw datasets for reliable analysis.

### Key Tasks Performed

- Created the `retail_analytics` database
- Inspected the structure and records of all three tables
- Corrected improperly imported column names
- Checked for missing values
- Checked for duplicate IDs
- Identified duplicate transaction records
- Created a cleaned transaction table using distinct records
- Converted `TransactionDate` from text format to the `DATE` data type
- Verified the transaction date range

### Data Quality Handling

During validation, a pricing discrepancy was identified in the transaction data.

The affected transaction price was corrected so that the transaction data remained consistent with the product information.

The corrected transaction data was then used for the subsequent exploratory and business analysis.

# Business Recommendations

Based on the analysis, the following actions could be considered:

### 1. Prioritize Home & Kitchen

Increase focus on **Home & Kitchen** inventory planning and promotional campaigns because it is the highest-revenue category and leads across the major customer locations.

### 2. Maintain availability of top-performing products

Ensure sufficient inventory for products such as **Product_17**, which combines strong revenue and unit sales performance.

### 3. Target the Mid customer segment

The Mid segment contains **559 customers**, making it the largest customer group.

Targeted promotions, bundles, or incentives could be used to encourage these customers to increase their purchase quantities.

### 4. Strengthen loyalty initiatives

Customers with high transaction frequency, such as **Customer 664**, could be targeted with loyalty programmes, personalized offers, and retention campaigns.

### 5. Use regional marketing strategies

Since Home & Kitchen leads across the major regions, regional campaigns can be tailored around category demand while monitoring location-specific performance.

### 6. Target high-revenue age groups

The Senior segment contributes the highest revenue and could be considered for targeted campaigns based on relevant product preferences and purchasing behaviour.

### 7. Maintain data-quality checks

Invalid demographic values, such as ages above 100, should continue to be flagged separately to prevent inaccurate segmentation and reporting.
